# 错误模型与安全响应

## 错误类别

错误码是稳定协议的一部分，编码和持久化宽度在 Phase 1 冻结。每个错误至少包含类别、详细原因、首次/最近时间、任务 ID、通道、原始上下文、是否锁存和恢复要求。

| 类别 | 示例 | 默认响应 |
| --- | --- | --- |
| `CFG` | CRC/版本/范围/缺少校准 | 禁止启动；保持全关，需重新加载有效配置 |
| `WEIGHT` | HX711 不响应、样本过期、漂移、超量程、未稳定 | 当前步骤停机；故障锁存，保存最近有效窗口 |
| `ACTUATOR` | I2C NACK、PCA9685 初始化/写回读失败、OE/功率级故障 | 立即 `stop_all`；无法确认全关时进入更高等级安全故障 |
| `SAFETY` | 急停、漏液/门禁/过流、互锁断开、硬件使能异常 | 立即关断并锁存；只有现场复核可清除 |
| `CONTROL` | 状态超时、过量、点动上限、交叉验证失败 | 关断并记录部分结果；按策略进入 `ERROR` |
| `RESOURCE` | 队列满、内存不足、栈余量不足、持久化失败 | 不开始/不继续加液；保留全关，报告诊断 |
| `SYSTEM` | 看门狗、异常复位、OTA/启动失败 | 由硬件保持全关；启动时禁止自动续泵 |
| `COMM` | 鉴权失败、格式错误、重复/过期命令、网络中断 | 拒绝该命令或进入离线；不影响正在运行的本地任务 |

## 严重度与锁存

- `FATAL`：无法证明执行器关闭、急停、过流、失控 PWM、数据损坏；锁存直到物理/人工复核。
- `STOP`：当前任务无法安全继续但设备可诊断；停机并需显式复位。
- `WARN`：不影响安全但质量/可观测性降级；不能被伪装成成功。
- `INFO`：生命周期和诊断事件。

错误清除必须满足：执行器已确认全关、触发源已消失、配置/校准有效、操作者权限和复核凭据有效。重复错误采用计数/退避，不能通过无限自动重试掩盖硬件故障。

## 故障响应顺序

1. 控制器或安全路径发出有界 `stop_all`，先触发独立硬件关断；不得等待 I2C 锁或普通命令队列。
2. 执行器服务随后清零 PWM 并尝试寄存器回读；回读只验证命令链，不能证明负载端断电。若输出状态不确定，必须由独立的硬件默认关断路径维持安全，并上报 `FATAL`。
3. 冻结当前任务结果和最近有效称重窗口，异步写入诊断事件。
4. 阻止新任务；必要时喂狗策略停止或触发安全复位，具体由验证后的系统监督设计决定。
5. 对外只发布经过脱敏的错误码、状态和相关性 ID；不泄漏密钥或任意硬件写接口。

## 证据要求

每个故障验收记录触发、机制、影响、日志/波形/回读证据和恢复动作。没有硬件注入能力的项目项标记 `[HW REQUIRED]`，不能以编译通过代替安全证明。
