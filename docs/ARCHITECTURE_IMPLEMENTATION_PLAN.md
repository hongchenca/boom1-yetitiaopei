# 全系统实施架构基线

日期：2026-09-26；网页/服务器交付边界更新：2026-09-27

本文冻结软件边界、实时调度、滤波管线、分阶段控制、HTTP 命令面及网页后台交付边界。网页和后台先在用户电脑进行局域网联调，再打包交给客户部署，详见 `WEB_SERVER_PLAN.md`。硬件相关的量程、流量、尾流和安全响应时间必须由标定/台架任务填写。

## 1. 运行边界

ESP32-S3 是本地控制器。液体控制闭环只依赖本地 HX711、PCA9685、配置和安全输入；HTTP、服务器、日志上传和网页都不能位于控制闭环的阻塞路径。服务器断开时，已经开始的自动任务继续按本地状态机运行；手动调试会话失联后由设备在期限内停机。服务器命令只能通过设备的 Command Service 排队、校验和授权。

任何时刻最多一个源泵输出非零，气路与泵互斥。`IDLE`、`PRECHECK`、`STOPPING`、`SETTLING`、`VERIFY`、`DONE`、`ERROR`、`ABORTED` 保持输出关闭。复位、看门狗、掉电、I2C 故障和网络故障不能依赖 HTTP 或普通 I2C 写零来保证安全，仍执行 ADR-0003 的独立硬件关断。

## 2. 组件与数据流

```text
HX711 x9 -> Weight Acquisition -> Filter/Stable Snapshot
                                      |
Local HTTP / Remote Adapter -> Command Service -> Dosing Controller
                                      |                    |
                                  Event Bus          Actuator Service
                                      |                    |
                               Storage/Upload       I2C -> PCA9685
                                      |
                              Local Web Status
```

组件职责固定如下：

| 组件 | 责任 | 禁止事项 |
| --- | --- | --- |
| `domain` | 类型、单位、范围、错误码、配方和纯质量运算 | 访问 GPIO/I2C、网络、文件和 FreeRTOS |
| `weight` | 九路 HX711 采样、原始值校验、校准、滤波、稳定快照 | 直接改变控制状态或写日志/网络 |
| `actuator` | PCA9685 I2C 所有权、输出仲裁、全关、硬件使能 | 接受 HTTP/网页直接写 PWM |
| `dosing` | 配方快照、阶段状态机、流量/尾流估计、点动和核验 | 阻塞等待网络/存储 |
| `safety` | 急停、互锁、驱动健康、超时、锁存和独立关断请求 | 被普通命令清除或绕过 |
| `command` | 命令 schema、鉴权、幂等、队列和取消优先级 | 直接触碰硬件 |
| `storage` | NVS 原子配置、任务结果、有限事件环 | 在控制周期同步写 Flash |
| `connectivity` | 本地 HTTP、远程服务器上传/命令适配 | 成为控制闭环依赖 |

## 3. 实时调度

所有控制状态、快照、队列和 DMA 数据放内部 RAM；PSRAM 只用于非实时大块缓存。时间使用 `esp_timer_get_time()` 或 FreeRTOS 单调 tick 转换的单调毫秒，禁止用墙钟判断超时。

| 路径 | 目标节拍/边界 | 优先级和阻塞规则 |
| --- | --- | --- |
| Safety/硬件关断 | 硬件路径即时；软件检查不超过 10 ms | 不能等待锁、队列、I2C、日志或网络 |
| Dosing Controller | 20 ms 控制 tick；每次只处理有限状态转移 | 高优先级、内部 RAM；单次执行不得做文件/网络 I/O |
| Weight Acquisition | 按 HX711 实际 SPS 采样；转换等待有上限 | 高于网络；不得假设九路同时完成 |
| Actuator Service | 单次 I2C 事务有界；更新失败立即全关并锁存 | 独占 I2C；不由 HTTP 直接调用 |
| Event/Storage | 有界队列异步消费 | 低优先级；满队列不能延长泵运行 |
| HTTP/Remote | 请求和响应均有读写/队列上限 | 低优先级；断网不影响本地任务 |

初始控制 tick 选 20 ms 只是调度上限，不代表称重每 20 ms 有新样本。`weight_max_age_ms`、I2C 最坏时延、停泵尾流、稳定窗口和看门狗余量必须由台架数据填写后才可放行泵。

## 4. 称重滤波与稳定判定

单路快照的处理顺序固定：

1. 检查 DOUT 就绪、原始值是否为有符号 24 位、通道和校准版本是否有效。
2. 将原始计数转换为 `int64_t mass_mg`，所有乘加使用溢出检查；失败样本标记 `fault`，不进入控制。
3. 对最近三个有效样本做 median-of-3，窗口不足时只发布 `valid=false` 的预热状态，不驱动阶段转移。
4. 对中值使用定点 EMA：`filtered += alpha_q16 * (median - filtered) / 65536`。`alpha_q16`、启动预热样本数和最大跳变均为配置项，禁止使用浮点或无界循环。
5. 维护固定长度稳定窗口。仅当窗口样本数达到要求、`max-min <= noise_band_mg`、线性斜率绝对值不超过 `slope_limit_mg_per_s`、样本未过期且没有故障时发布 `stable=true`。
6. 输出原始值、滤波值、窗口跨度、估计噪声、斜率、时间戳、校准版本和降级原因，供控制器和日志使用。

滤波器只延迟和标记数据，不能“修复”断线、超量程或未来时间戳。控制器只消费有效且未过期的滤波快照；`stable=false` 的样本可用于趋势估计，但不能作为最终结算。

## 5. 分阶段调配控制

每个任务启动时复制不可变 `Recipe + ControlConfig + CalibrationSnapshot`。运行中配置更新只影响下一个任务。

1. `PRECHECK`：验证配方、通道校准、源库存、中央秤、PCA9685 全关、硬件使能和急停状态。
2. `FAST_FILL`：使用保守的 `fast_duty_percent`，仅在有效源秤快照下运行；剩余量低于 `slow_entry_mg` 或达到阶段时间上限时转慢速。
3. `SLOW_FILL`：使用 `slow_duty_percent`，用稳定样本估计质量速度，剩余量低于 `fine_entry_mg` 时转精加。
4. `FINE_FILL`：使用 `fine_duty_percent`，计算 `predicted_tail_mg = bounded_rate * bounded_stop_latency`，达到 `target - fixed_overshoot_mg - predicted_tail_mg` 后停止。
5. `STOPPING`：先触发独立硬件关断，再请求 PCA9685 全关；确认命令链结果，记录尾流起点。
6. `SETTLING`：等待源秤和中央秤稳定窗口；超时、过期或故障不当作成功。
7. `JOG_FILL`：不足目标时执行有限次数、有限时长、有限质量的点动；每个脉冲后都必须回到 `STOPPING -> SETTLING`。
8. `VERIFY`：计算源秤失重、中央秤增重和质量差值，按 `explainable_band / warning_band / fault_band` 分类；未完成标定时只能记录，不能宣称通过。

过量、传感器失效、I2C 写/回读失败、阶段超时、急停、队列满或配置错误都走 `stop_all -> ERROR`。不允许倒吸假设、无限点动、无限重试或用网络响应代替物理完成。

## 6. 配方和固定调配

固定配方包含：`recipe_id`、版本、显示名称、步骤数组、每步 `source_scale_id`、目标质量 mg、允许误差 mg、快/慢/精入口、占空比上限、最大阶段时间、点动限制、质量守恒带、校准兼容范围和 CRC。步骤只能引用 0~7 源秤，中央秤为验证秤；保留通道不能被配方引用。

设备保存双槽原子配置；服务器保存配方的发布版本和审计记录。设备接收配方后先校验 schema、范围、CRC、硬件兼容和校准版本，再允许提交任务。任务执行记录固定引用配方版本、配置版本和校准版本。

## 7. HTTP 与本地网页

完整网页由电脑/服务器后台托管，浏览器通过同源 HTTP 提交操作、SSE 接收状态，设备主动上传状态并领取命令。界面、实时调参和接口分组见 `WEB_SERVER_PLAN.md`。设备侧本地 HTTP 可作为轻量维护入口，下表为原有设备侧接口，不是完整后台 API：

| 方法 | 路径 | 语义 |
| --- | --- | --- |
| `GET` | `/api/v1/status` | 一致性只读状态快照 |
| `GET` | `/api/v1/events?after=` | 有界事件读取 |
| `GET` | `/api/v1/recipes` | 已验证配方元数据 |
| `POST` | `/api/v1/jobs` | 提交固定配方任务，返回 request/task 状态 |
| `POST` | `/api/v1/jobs/{id}/cancel` | 幂等取消，优先级高于普通命令 |
| `POST` | `/api/v1/faults/ack` | 仅授权操作者确认，不能自动清除安全故障 |
| `GET` | `/` | 本地静态调试页面 |

所有改变状态的请求都带 `request_id`、协议版本、设备 ID、来源、过期时间和会话身份；重复请求返回原业务结果。网页不能调用 GPIO、I2C、PCA9685 或无约束的占空比接口。调试模式可提交经设备范围校验的速度/点动请求；页面区分请求值、设备生效值和保存版本。前端通过本机后台与模拟设备联调，不能用静态页面点击效果代替命令执行回执。

## 8. 独立后台、日志上传和客户部署

客户服务器由客户运维管理，不提供开发方权限。新增网页/后台建议放在 `E:\111111111\yeti\fwq\yetitiaopei_app\`，保留已有其他文件。FastAPI + 专用 SQLite 后台与 Vue 页面先在用户电脑运行，再交付独立服务包；不依赖客户既有业务 API。最终环境参数仅影响打包、代理与配置，不能阻断本机开发。

设备上传实时遥测、脱敏事件和任务结果，包含设备/任务/步骤 ID、request_id、单调时间、样本序号、状态、质量、错误码和配置/校准版本。日志采用有界缓存与幂等 event_id、超时、退避和断点确认；安全/失败/完成事件优先，关键存储容量不足时拒绝新任务并告警，不能阻塞停止或控制任务。后台命令由设备主动长轮询领取，再进入 Command Service；长轮询不能阻塞状态上传和调试续期。

## 9. 实施顺序

1. `TASK-DOMAIN-004`：控制配置、配方、事件和错误码纯数据模型。
2. `TASK-WEIGHT-004`：滤波、稳定窗口和质量运算，主机边界测试；HX711 驱动另行任务。
3. `TASK-DOSING-004`：分阶段控制纯逻辑状态机和确定性仿真，不接泵。
4. `TASK-ACTUATOR-004`：PCA9685 服务、全关、回读、独立关断接口；依赖台架实测。
5. `TASK-HTTP-004`：设备主动连接后台，上传状态/结果并领取命令，只接 Command Service；设备本地维护页可后续实现。
6. `TASK-STORAGE-004`：双槽配置、任务结果和事件环。
7. `TASK-SERVER-004`：独立后台、网页、模拟器与客户部署包，新增 `fwq\yetitiaopei_app`；可先用模拟数据开发，不依赖客户服务器权限或硬件到货。
8. `TASK-INTEGRATION-004`：仿真、台架、传感器和负载端验收；硬件证据不足时不得进入真实调配。

固件构建与刷机按对应任务和用户授权执行；网页/后台任务包含本机启动、测试及部署演练。每个任务将报告写入 `docs/agent_reports/TASK-<ID>.md`。

## 10. 当前阻断项

- HX711 尚未到货，九路采样、噪声带、滤波 alpha、稳定时间和校准不能实测冻结。
- 泵、MOSFET、气路和独立关断拓扑未核验，不能开启真实输出。
- PCA9685 已确认 I2C 通讯，但频率、OE、电平和负载端输出尚未验收。
- 页面/后台可先开发，当前固件尚未实现设备通信与调试会话能力；实机联调依赖相关接口任务完成。
- 最终客户部署需确认运行环境、端口/URL、证书和设备网络路径；Wi-Fi、凭据及硬件能力影响实机接入，不影响模拟页面开发。
