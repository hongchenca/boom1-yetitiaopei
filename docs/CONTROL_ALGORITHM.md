# 定量控制算法（0.6.1 已实现行为）

内部统一使用整数 mg、ms；硬件输出由 `actuator` 独占访问。`dosing_controller.c` 是不依赖 RTOS/I2C 的纯状态机，`dosing_service.c` 负责采样快照、输出应用、期限与 NVS 位置保存。

## 剂量与废液

每步剂量以中央秤增重为准：`delivered = vessel_now - vessel_start`。源秤减重只用于库存、损失上限与质量平衡核验，因为吹出的残液进入废液口。

任务最多 8 步，每步指定源通道、目标与容差。预检查要求本批涉及的源秤与中央秤有效且稳定，校准版本被冻结；未涉及的源秤不阻塞任务。源秤必须读剩余液体净重，不能带满瓶去皮后把负数当库存。目标加容差及每步残液预算不能超过可用库存，容器当前重量加各步预算不能超过容量。

## 三种重量

- `control_mg`：median3 + 1/2 EMA，用于运行中预停与保护；Q16 累加避免整数死带。
- `filtered_mg`：median5 + 自适应时间常数 EMA，用于显示。网页附加平滑不参与控制。
- `stable_mg`：16 个原始样本的平均，仅在原始峰峰值合格并连续 500 ms 后有效。最终核验要求整个窗口来自停泵以后。

样本超过 500 ms 失效。读取错误、ADC 饱和或连续未就绪超过 300 ms 清空窗口。10 SPS 下完整窗口约 1.5 秒，加上稳定驻留，不能把平滑显示当成真实稳定。

## 加液与补液

快速默认 75%，慢速 50%，精加 45%，液泵非零下限默认 40%。不能通过下发死区内 PWM 获得更小流量；小剂量以有效占空比短脉冲实现。起转下限、最短脉冲、输出对应流量须在实际 50 Hz 和管路负载下标定。

连续加液时，每至少 200 ms 的新快通道样本估算流速，并以 1/2 平滑更新。换向等待结束时重建估算起点，避免把到位等待计入流量时间。超过 `max_flow_mg_s` 立即报 `flow_limit` 并停止。

`预测尾流 = 流速 × (tail_ms + 滤波延迟 + 样本年龄 + 20 ms 控制节拍) / 1000 + compensation_mg`。

滤波延迟预算上限为 500 ms。预测值最多取本步目标，不用慢速切换阈值裁剪。剩余量接近慢速阈值加预测尾流时减速，接近预测尾流或精加阈值时停泵。预测只用于提前停止，不作为配液完成依据。

停泵后重新等待稳定窗口：剂量不足则按剩余量与流速估算补液脉冲，并限制在 `pulse_min_ms..pulse_max_ms`，每次之后再次停泵判稳。没有流速估计时用最短脉冲。达到目标容差才切废液位置；超量不能通过倒吸补救。

无进展计时累计实际指令启泵时间；补液间的判稳等待不计入，也不清零。只有容器增重量达到 `progress_mg` 才清零，避免短脉冲不停重置保护。`max_jogs`、单步/整批期限提供额外上限。

## 清液与最终核验

每步稳定合格后记录容器/源液重量，切废液位置，等待 `route_ms`，再按 `air_percent` 吹气 `purge_ms`。等待从舵机指令应用完成后计时；当前没有机械位置传感器。

吹气时监控容器快通道变化；停气后再次获取新鲜稳定窗口。中央变化不得超过 `purge_leak_tolerance_mg`，源液变化不得超过 `balance_tolerance_mg`，并重新检查本步目标容差及 `源秤减重 - 容器增重` 是否落在 `[-balance_tolerance_mg, residual_limit_mg + balance_tolerance_mg]`。最终单步记录采用清液后的重量，不能用较大的清液阈值放宽配方容差。全部步骤通过后还校验整批中央增重。

## 控制期限与边界

服务约每 20 ms 运行，输出本地租约 300 ms，剩余不超过 120 ms 时续租；脉冲及吹气还有各自硬截止。控制节拍间隔超过 300 ms、输出租约意外丢失、称重失效、校准变化、外部停止或驱动故障均终止任务，不自动续跑。全停代次在每次输出前复核，阻止迟到启泵。

NVS 和网络不在控制任务路径。每个 I2C 事务超时上限 100 ms；驱动独立期限任务和共享 OE 负责关断。相同输出续租不切 OE；改变输出仍有短暂共享 OE 禁能，真实舵机波形与负载响应需要实测。

当前结果在设备 RAM 和后台遥测历史中，不具备设备掉电后的批次结果恢复。显示噪声降低、主机替身测试与编译通过不代表达到实际配液容差。
