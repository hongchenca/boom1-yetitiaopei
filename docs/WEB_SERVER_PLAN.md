## 本阶段实施记录（优先于后文原始技术建议）

- 当前应用位于本工程 web_server/，使用 Node.js 24.14.x 标准库、node:sqlite 和原生 HTML/CSS/JS，无 npm 依赖或前端构建。原 Vue/FastAPI/兄弟目录建议暂不采用；未修改 fwq 或客户资料。这是优先完成 LAN 联调的阶段选择，并非 Python 不可用。

## 1. 开发和交付边界

交付一套独立的网页、后台、专用数据存储、设备通信协议和部署资料。客户服务器作为运行环境，不要求读取其他业务源码、复用其他业务数据库或接入其内部 API。

| 阶段 | 网页和后台在哪里运行 | 设备连接地址 | 谁负责启动和维护 |
| --- | --- | --- | --- |
| 页面开发 | 用户电脑，使用模拟设备 | 本机模拟器 | 开发方 |
| 局域网实机调试 | 用户电脑 | 电脑局域网 IP 和配置端口 | 开发方与用户 |
| 交付前演练 | 本机隔离环境或另一台测试机，使用交付包 | 演练服务地址 | 开发方 |
| 客户部署 | 客户分配的独立服务目录或容器 | 客户提供的可达服务地址 | 客户运维 |

电脑、手机和平板通过浏览器访问同一后台提供的页面。电脑本机可使用 `http://127.0.0.1:8000/`；其他局域网终端和 ESP32 使用电脑的实际局域网 IP，例如 `http://192.168.1.100:8000/`。这些地址是示例，端口可配置，`0.0.0.0` 仅用于监听。

局域网模式显式监听 `0.0.0.0`；按实际端口设置 Windows 防火墙入站规则，确认同一网络可达、无线 AP 没有客户端隔离。联调期间电脑保持运行；固定地址或 DHCP 保留避免设备端地址失效。

## 3. 通信路径

```text
浏览器 --HTTP 操作 / SSE 状态--> 本机后台或客户后台
                                       ^
                                       | ESP32 主动建立连接
                                       | 遥测、事件、回执；长轮询领取指令
                                       v
                              ESP32 Command Service
                                       |
                           本地控制器 -> 执行器与称重
```

局域网和客户部署使用同一设备通信协议。交付时更换服务 URL、设备凭据和证书配置，复用已验证的业务代码。客户服务必须能被设备所在网络访问；若网络隔离，由客户提供内网路由、VPN 或网关。部署到服务器本身不能解决网络不可达。

设备主动长轮询待执行命令，服务端在命令到达时立即返回；25 秒为无命令时的等待上限，不是每条命令固定延迟。设备空闲轮询、遥测上传和回执各有超时与退避。长轮询不能阻塞遥测、停止回执或调试会话续期。

浏览器用 SSE 接收状态，HTTP 提交操作；断线先获取完整快照再恢复增量事件。原方案每 2 秒一批的数据可用于历史汇总，但实时调试另设更快通道：初始设计目标为活动设备约 5 Hz 状态上报、空闲约 1 Hz，前端按最新有效样本绘图。此值为可调联调目标，需测量 CPU、网络和队列负载后确认；不能把网页刷新率等同于 HX711 采样率或本地控制 tick。

状态带设备 ID、boot_id、样本序号、设备单调采样时间、样本年龄、后台接收时间、配置版本和来源（模拟/实机）。重复快照不生成新测量点；离线或陈旧时保留最后值并标示失效，曲线断开，禁止用插值伪造新读数。

## 4. 网页页面与样式

默认设计方向：中文工业控制台，浅灰背景、白色卡片、深蓝导航，状态用颜色、文字和图标同时表示。桌面以 1440 px 宽度为主要设计尺寸，并适配常用笔记本和手机；触摸操作不依赖悬停。保持数值、单位、目标、实际值和操作回执清晰可读。

| 页面 | 主要内容 |
| --- | --- |
| 总览 | 在线设备、当前任务、八个源通道卡片、中央秤、告警、最后更新时间和停止入口 |
| 实时调试 | 原始/滤波称重曲线、通道选择、目标与实际值、占空比请求/生效值、参数修改和回执 |
| 配方与配液 | 配方版本、各原液目标/容差、串行步骤、开始/取消、阶段进度及最终误差 |
| 标定 | 去皮、砝码输入、结果预览、版本确认、泵与尾流测量记录 |
| 参数 | 分组参数、单位/上下限、设备当前值、待提交值、保存和生效时机 |
| 记录与告警 | 配液记录、操作记录、故障时间线、筛选和导出 |
| 系统设置 | 服务/设备连接状态、用户角色、版本信息、备份和诊断摘要 |

页面始终区分“模拟设备”和“实机”。命令提交后显示待执行/执行中，收到设备回执才显示已生效；按钮点击或 HTTP 202 不能当作动作完成。网络停止按钮是软件停止请求，不能标成硬件急停；连接不可达时明确显示无法确认停止。

页面主版本部署在电脑/服务器。ESP32 内置页面若后续需要，只承担轻量状态、配网和维护；完整控制台不必塞入固件，也不依赖该页面才能联调。

## 5. 实时调参的生效规则

| 参数或操作 | 生效时机 | 约束 |
| --- | --- | --- |
| 曲线范围、显示单位、刷新偏好 | 浏览器立即生效 | 不改变设备控制 |
| 调试会话中的速度请求、有限时长点动 | 设备校验后在控制边界应用，并回报结果 | 使用设备公布的白名单和范围；单泵与气路互斥；有会话期限和独立运行上限 |
| 配方、目标量、自动配液阶段/滤波参数 | 可在线编辑和保存，下一次自动任务使用 | 当前自动任务继续使用启动时的不可变快照 |
| 称重标定、PWM 公共频率、硬件映射 | 停机维护或专门标定流程 | 不允许通过普通滑块即时改写 |

支持调试模式内的即时调节，同时保持自动配液批次可追溯。页面在参数旁明确显示“立即应用”“下次任务生效”或“需停机”。自动任务中途修改目标或算法不在首版范围内，需要另外定义状态转移和计量记录。

即时调试依赖设备端会话管理：仅停机且硬件条件满足时取得控制权；同一设备一次只允许一个操作者持有。后台提供界面和转发，设备重新校验权限、参数范围、配置版本、会话序号和动作期限，最终由 Actuator Service 执行。

调试持续运行需要短期会话续期，使用设备单调时间限制期限，并设置独立的最长运行时间/最大输出上限。浏览器不再活跃、后台退出或网络中断时，设备在本地期限内停止并注销控制权；后台不能脱离活跃操作者无限续期。过期、旧会话、旧 boot_id 和乱序请求不执行，调试启动命令不离线排队补发。停止请求优先处理，即使调试会话已失效也不能因普通队列满而被挡住。

滑块在拖动期间显示草稿，提交时合并连续修改，按序发送，避免每个鼠标事件都写设备。持久化另用显式保存操作，经设备确认和原子存储后才显示“已保存”；即时修改只在本次会话 RAM 中应用，不按刷新周期写 NVS。

调试会话断线即停止；已开始的自动配液则继续按本地状态机和本地故障条件处理。两种断线行为在页面和协议中均明确区分。

## 6. 接口与命令闭环

后台提供 `/api/v1/` 版本化 API，实施时生成 OpenAPI 和模拟 fixtures。浏览器端与设备端入口分开鉴权，设备身份从凭据绑定，不信任请求自行指定另一个 device_id。

| 方向 | 接口组 | 作用 |
| --- | --- | --- |
| 浏览器 -> 后台 | `/auth/*`、`/devices`、`/devices/{id}/status`、`/stream` | 会话、设备列表、状态与 SSE |
| 浏览器 -> 后台 | `/devices/{id}/jobs`、`/devices/{id}/jobs/{job_id}/cancel` | 开始/取消自动任务 |
| 浏览器 -> 后台 | `/devices/{id}/config`、`/recipes`、`/devices/{id}/calibrations` | 配置、配方、标定 |
| 浏览器 -> 后台 | `/devices/{id}/debug-sessions/*`、`/devices/{id}/stop` | 受控调试、参数应用、续期、停止 |
| 设备 -> 后台 | `/device/telemetry`、`/device/events`、`/device/dose-records` | 状态、事件、任务结果上传 |
| 设备 -> 后台 | `/device/commands/poll`、`/device/commands/{id}/ack` | 领取命令、回报接收/执行/完成/拒绝 |

完整路径由服务前缀加上表路径构成。请求关联 `request_id`、`command_id`、设备/会话、schema 版本、过期时间、期望配置版本；设备回执带实际生效版本/值和失败原因。相同 request_id 不重复执行。状态至少区分排队、送达、设备接受、运行、完成、拒绝、过期和执行结果未确认；超时或丢失回执时先查询设备状态，不能换新 ID 重发开泵。

后台重启从持久命令表恢复并与设备核对；轮询通过异步通知及时唤醒，超时和离线命令不能复活。自动任务取消和停止有优先通路。多个浏览器同时编辑使用期望版本检查，冲突时重新读取，不静默覆盖。

本地页面开发用模拟设备实现相同协议和命令状态，模拟数据单独存储。实机尚未支持的能力由 capability 明确标记，相关按钮禁用；接真实设备不等于具备称重或开泵能力。

## 7. 数据和运行配置

配置至少包含监听地址/端口、服务 URL、`APP_BASE_PATH`、数据/日志路径、模拟开关、登录配置、设备凭据和连接超时。浏览器使用相对 API/资源地址；子路径部署时，静态资源、页面路由、API、SSE 和反向代理前缀必须一起验证。

局域网实机操作也要求登录与设备身份校验。用户分查看、操作和维护权限；调试/校准需要维护权限。会话、密码和设备密钥不写入源码或默认共享账号；`.env.example` 仅列占位配置。客户生产部署使用 HTTPS，设备校验证书，模拟模式关闭。

保存设备、配置版本、配方、命令回执、配液结果、操作审计和事件。曲线数据按配置聚合和保留，限制数据库/日志容量；安全事件优先保留。有限存储不能承诺无限断网期间无丢失：未确认关键记录达到容量门槛时拒绝新自动任务并告警，停止和关断不受影响。已有任务的最终记录保留空间需在启动前预留；恢复上传按 event_id/序号确认并去重。

## 9. 实施顺序与验收

1. `TASK-SERVER-004` 先冻结 API/schema，建立后台、SQLite、模拟设备、命令回执及启动方式。
2. 同一任务的前端子阶段完成页面样式、九路曲线、参数表单、配方、告警和模拟交互。模拟页面须经过浏览器实际检查。
3. `TASK-HTTP-004` 在固件中实现设备主动连接、遥测、命令和回执适配。调试会话所需 domain/command/control/actuator 能力另拆任务，禁止用 HTTP 回调直接控制输出。
4. 局域网联调：本机和另一台终端访问，验证真实样本、应用回执、版本冲突、过期/乱序、停止优先级、浏览器关闭、电脑休眠/后台重启和设备重启。硬件未验证时仅使用模拟器和已具备的只读能力。
5. 从干净目录启动交付包；验证根路径/子路径、指定端口、数据持久化、备份恢复、升级回滚、停机/离线记录及客户部署说明。若客户要求离线安装，再在断外网环境演练依赖安装。

测量并报告“点击 -> 后台接收 -> 设备应用 -> 页面显示”的端到端延迟和样本年龄，记录分位值与最大值；时效目标待局域网实测确认。网页操控不承担硬实时关断职责。硬件闭环仍按原有硬件/计量任务验证。
