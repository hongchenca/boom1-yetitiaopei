# 项目需求与边界

项目：八通道智能液体定量调配系统。本文是需求基线；设计决策见 `SYSTEM_ARCHITECTURE.md`，未确认事实不得写成硬件规格。

## 已知输入

- 用户确认主控模块为 ESP32-S3-WROOM-1-N16R8，使用 ESP-IDF 与 FreeRTOS；按料号配置 16 MB Flash、8 MB PSRAM，实际板上容量及启动行为仍须实测。
- 0~7 号原液容器各有一组 Load Cell + HX711；8 号为中央调配容器，合计九组。
- 八台直流蠕动泵和一路气路；PCA9685 经 I2C 输出 PWM，再由外部 MOSFET 功率级驱动负载。暂定 CH0~7 对应 Pump0~7、CH8 对应 Air Purge，CH9~15 保留。模块标称 40~1000 Hz，实测适配性 TBD。
- 各原液的计量主依据为源容器减重；中央秤用于总量监控、结果核验及异常检测。

## 网页、局域网与交付边界

- 页面、后台、专用数据库和模拟器组成独立应用，先在开发电脑运行，通过局域网访问和调试 ESP32；开发不依赖客户服务器账号、源码、数据库或既有 API。
- 局域网实机操作使用登录、角色权限和设备身份校验。浏览器提交操作后以设备回执确认实际生效值；HTTP 接收成功不等于泵或参数已执行。
- 客户最终接收同一应用的版本化部署包，由客户在隔离目录/进程/数据目录中部署。监听端口、服务 URL、子路径、证书、数据路径和离线安装方式作为交付适配输入，由客户运维合并其代理或防火墙配置。

## 产品行为

1. 自动定量任务在网络断开时继续运行；实时调试会话失去浏览器/后台续期后由设备租约到期停止输出。网络、日志和 OTA 不能抢占关键控制时限。
2. 配方必须先通过身份、格式、范围、库存、传感器及安全状态校验，再进入控制器。每种原液的目标质量与允许误差均需明确。
3. 上电、重启、看门狗复位、异常退出和 OTA 前后，所有泵及气路应进入可证明的关闭状态；无法证明关闭时禁止投入运行。
4. 控制器采用快加、慢加、精加、提前停泵、稳定等待、必要时点动、最终核验。每一步有超时和安全退出路径。
5. 用时间对齐的稳定窗口比较源容器失重总量与中央容器增重；必须考虑管路残液、飞行液体、滴液、停泵惯性、振动和滤波延迟。瞬时值不可直接作为质量一致性结论。
6. 所有影响剂量、安全与时序的参数都有版本、单位、范围和出厂默认策略；无有效配置时禁止启动泵。
7. 每次任务保存命令来源、配方版本、配置版本、结果、误差、异常与人工处理信息；记录操作不得阻塞控制循环。

## 首版范围与待确认需求

- 首版同一时刻只允许一台泵工作，气路只在所有泵停止并经过明确安全条件后独占工作。这样可独立归因源秤变化及中央增重；吞吐量目标 TBD，若要求并行，须另立 ADR 与验证方案。
- 启动、暂停/恢复、取消、远程接口、配方编辑、清洗和排空的产品流程仍 TBD。首版安全契约规定任何来源的取消都走控制服务并关断执行机构；暂停/恢复在需求冻结前不承诺。
- 精度、重复性、最大批量、最大单通道剂量、作业节拍、可用性、寿命及液体种类/黏度/密度范围 TBD。没有这些数据不能宣称计量性能合格。
- 网络与云端不是自动定量闭环的依赖；网页联调首版采用 HTTP/SSE 后台和设备主动上报/长轮询，具体 TLS、证书和 OTA 策略仍在网络任务中冻结。

## 当前仓库基线

当前仍只有 ESP-IDF `hello_world` 示例。2026-09-24 已将 `sdkconfig.defaults`/`sdkconfig` 设为 ESP32-S3、16 MB Flash、Octal PSRAM 80 MHz、启动自检和显式 PSRAM 分配；分区仍为单应用，未配置 OTA。`sdkconfig.old` 是 ESP32 目标的历史文件，不能作为当前板卡证据。板上容量及引脚/关断路径尚未验证；本示例不具备控制功能。
